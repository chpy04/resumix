# T16 — quality pass

Branch: `feat/t16-quality-pass`, off `feat/t15-feedback-polish`. Worked in the
main checkout; no other task in flight.

## Why

The ask was "convert the JavaScript to TypeScript, and check the repo upholds
the standards in `.claude/`". The first half turned out not to exist; the
second half found four things.

## The JavaScript question

There is none worth converting. `tsconfig.json` already sets `allowJs: false`,
and the tree is 105 `.ts` + 27 `.tsx` files against four non-TS files, three of
which must stay that way:

| file                        | why it stays                                                                                                                                    |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `public/pdf.worker.min.mjs` | vendored pdf.js build artifact, hand-copied so it cannot version-skew against the bundled `pdfjs-dist` (CLAUDE.md, "Traps already discovered") |
| `services/latex/server.js`  | `.claude/rules/render-latex.md`: "dependency-free CommonJS Node … no TypeScript, no bundler. Keep it that way." TS adds a build step to a container that is deliberately small and auditable |
| `postcss.config.mjs`        | one line; Next.js does not support a `.ts` PostCSS config                                                                                       |
| `eslint.config.mjs`         | ESLint can load `eslint.config.ts`, but only via `jiti` — a dependency for something with no problem to solve (CLAUDE.md, "How to work here")  |

Nor is there JavaScript-shaped code hiding inside the `.ts` files: one `any` in
the tree (`lib/queries/selections.ts:44`, drizzle's transaction generic, with a
disable comment), 23 type assertions all of which are load-bearing, and
`strict` + `noUncheckedIndexedAccess` + `verbatimModuleSyntax` +
`erasableSyntaxOnly` all on.

## What the audit found clean

Worth recording so the next pass does not redo it: all 22 route handlers open
with `requireUserId` and wrap in `withApiErrors`; all 22 paths appear in
`docs/API.md`; no `{ ...row }` spread escapes `lib/queries/**`; no exported
symbol in `lib/**` or `components/**` is unreferenced; `getSelections` takes no
`userId` but every caller resolves the resume through `getResumeRow(userId, id)`
first, which is what proves ownership (and says so in a comment).

## The four fixes

### 1. `warning` had no colour tokens

`PreviewPane` held the last two raw palette shades in the app — the
render-warnings banner (`border-amber-800/50 bg-amber-950/20 text-amber-300`)
and the multi-page badge (`border-amber-700/60 bg-amber-950/40 text-amber-300`).
`.claude/rules/styling.md` bans these by name, but ESLint cannot see a Tailwind
class, so the ban is prose only.

The cause is worth naming: `--color-warning` existed as a *single* value, while
`danger` had a five-token family. There was nothing to reach for, so the banner
invented its own shades — which is precisely how the rule says drift starts.
`warning` now mirrors `danger`: `ink` / `surface` / `line` / `line-strong`,
mapped to the exact shades that were already hardcoded, so this moved no pixels.

### 2. `forwardRef` (D-024)

`SearchBox` and `TemplateEditor` were the only components not shaped as
`export default function Name(props: NameProps)`, and `forwardRef` was the sole
reason. React 19.3 passes `ref` through as an ordinary prop, so the wrapper is
legacy API. Both are now plain functions with `ref?: Ref<T>` in their props
interface, and both callers (`ResumeGrid`, `TemplateTab`) were already passing a
`useRef` and needed no change.

### 3. A dead ref

`TemplateEditor`'s `gutterRef` was assigned to the gutter `<div>` and never
read — the gutter follows the textarea via a `transform` computed from
`scrollTop` state. Removed, along with the now-unused `useRef` import.

### 4. The latex-unavailable response was duplicated and half-untyped

`/render` and `/pdf` both flatten `LatexServiceError` into a 200. `/render`
built it as a typed `RenderResult`; `/pdf` built the same fields as a bare
object literal, so nothing checked it against the type. That is the widening
`.claude/rules/data-access.md` warns about, one layer up from the query layer,
and it would have gone unnoticed until a client depended on a field `/pdf`
silently stopped sending.

Both now call `latexUnavailableResult(err, warnings)` from `lib/latex.ts`,
which returns `RenderResult`. Placed there because that module owns
`LatexServiceError`, and deliberately *not* folded into `compileTex`:
`.claude/rules/render-latex.md` requires that a compile error (a result) and an
unreachable service (a throw) stay distinct all the way up. They still do —
they converge only in the handler, which is the layer that owes the caller a
200 either way. 2 unit tests in `lib/latex.test.ts`.
