# T5 — seed script

## What was built

Files added under `scripts/**` and `lib/seed-data/**` (the only files this task owns):

- `lib/seed-data/v1-resume.ts` — typed, id-free transcription of `docs/reference/v1-resume.tex`:
  `V1_EXPERIENCES` (3 experiences, 4/5/5 bullets), `V1_PROJECTS` (3 projects, 2 bullets each), and
  `V1_SKILL_ROWS` (3 top rows — Languages / `Frameworks \& Tools` / Cloud Technologies, `separator:
  ', '` — and 2 bottom rows — Interests / Accolades, `separator: ' $|$ '`, per D-013). Content is
  the exact same strings as the `v1Library` fixture in `lib/render/render.test.ts` (copy-checked,
  not re-keyed by hand, per the task brief) — raw, unescaped LaTeX per D-008, including
  `\textbf{}`, `\href{}{\underline{}}`, `\$`, `\&`, `\%`, and the two verbatim trailing spaces
  ("Racket ", "Vercel ") the original author typed.
- `scripts/seed.ts` — the seed script. Opens its own `postgres`/`drizzle` client (does **not**
  import `lib/db/index.ts`, which does an extensionless `import './schema'` that Node's ESM
  resolver can't follow when run directly with `--experimental-strip-types` — verified this fails
  with `ERR_MODULE_NOT_FOUND` before working around it; `lib/db/schema.ts` itself has no relative
  imports, so importing it directly with an explicit `.ts` extension works fine). Logic:
  1. If a default template already exists and `--force` was not passed: print "already seeded"
     and exit 0. This is the idempotency guard the task asked to prefer over blind upserts.
  2. If `--force` was passed: `TRUNCATE` all 15 content + bridge + resume tables (`CASCADE`,
     which — unlike plain `DELETE` — ignores the `RESTRICT`/`CASCADE` per-column delete actions,
     so this one statement can wipe everything regardless of FK direction) and reseed from
     scratch.
  3. Otherwise (first run): insert the default template (`DEFAULT_TEMPLATE`, `name: 'Default'`,
     `isDefault: true`), all content from `lib/seed-data/v1-resume.ts`, and a `Default` resume
     (`isDefault: true`) with every experience/project/skill-row/bullet/skill selected via the
     bridge tables, dense 0-based `sort_order` in reference-file order, scoped per SCHEMA.md
     (bullet order restarts at 0 per parent item; skill order restarts at 0 per row). All of this
     — content inserts, the resume, and every bridge row — happens inside one
     `db.transaction(...)`.
  4. Prints a summary (counts of each content type + the resume id) on success.
- `scripts/smoke.ts` — the end-to-end smoke test the task asked to keep. Read-only: opens its own
  DB connection, loads the `Default` resume + its template, reconstructs the full `Library` and
  that resume's `Selections` from the bridge tables' `sort_order` (exactly as an API handler would
  build the `GET /api/resumes/:id` payload), calls `renderResume()` from `lib/render`, diffs the
  result against `docs/reference/v1-resume.tex` with the same insignificant-whitespace
  normalization and the same documented one-line divergence strip that
  `lib/render/render.test.ts`'s round-trip test uses (re-implemented here rather than imported,
  since this script intentionally doesn't depend on a `*.test.ts` file), then POSTs the rendered
  tex to the latex service via `lib/latex.ts`'s `compileTex()` and asserts `ok: true` and
  `pages: 1`. Exits non-zero if either check fails.
- `.gitignore` — added `scripts/.scratch/`, matching the existing `lib/render/.scratch/` entry;
  both `render.test.ts` and `smoke.ts` write their rendered output there for inspection.

No other files were touched. `lib/render/**`, `lib/db/schema.ts`, and
`docs/reference/v1-resume.tex` are all unmodified.

No diff was printed because `normalizedActual === normalizedExpected` — the round trip is a clean
match (the script only writes/prints a `diff -u` when they differ). Data read out of the database
via Drizzle, run through `renderResume()`, reproduces `docs/reference/v1-resume.tex` byte-for-byte
modulo insignificant whitespace, and the one documented, expected divergence:

> The reference file contains a commented-out placeholder line inside Experience #1's item list
> (`  % \resumeItem{Built \textbf{AWS} infrastructure ...}`) — a LaTeX comment the original author
> left as a note-to-self. LaTeX comments have zero effect on the compiled document, and the render
> engine has no concept of "a comment living inside token-owned content" (the whole bullet list
> there is data-driven, sourced from `experience_bullet` rows), so this line cannot be reproduced
> by any data-driven renderer. `lib/render/render.test.ts` already documents and strips this exact
> line for its round-trip assertion; `scripts/smoke.ts` does the same, calling out the specific
> line so a future accidental edit to the reference file (which would silently defeat this check)
> is loud instead of silent.

The rendered `.tex` then compiled successfully against the real `pdflatex` sidecar
(`services/latex`), producing exactly one page, confirming the project's governing constraint —
"I should always be able to represent my current resume within the project" — holds for the
seeded data end to end: DB → renderer → LaTeX → PDF.

## Design notes / deviations

- **Idempotency guard, not upsert.** The presence of any `is_default = true` template is treated
  as "already seeded." This is intentionally coarse (it doesn't try to reconcile partial/failed
  prior seeds row by row) — the task asked for a guard over blind upserts, and a from-scratch
  domain like this (a handful of content rows, no user data to preserve on a fresh dev DB) doesn't
  benefit from finer-grained upsert logic. `--force` is the escape hatch for "start over," and it
  uses `TRUNCATE ... CASCADE` specifically because a plain `DELETE` would have to fight the
  `experience`/`project`/`technical_skill_row` tables' `ON DELETE RESTRICT` on their bullet/skill
  children in exactly the wrong order; `TRUNCATE CASCADE` sidesteps that by design.
- **Own DB connection instead of `lib/db/index.ts`.** As noted above, `lib/db/index.ts`'s
  extensionless internal import breaks when the file is loaded directly by
  `node --experimental-strip-types` (only Next.js's bundler tolerates it). `scripts/seed.ts` and
  `scripts/smoke.ts` each open a short-lived `postgres()` + `drizzle()` client scoped to the
  script's `main()`, mirroring `scripts/migrate.ts`'s existing pattern rather than fighting the
  singleton. I did not touch `lib/db/index.ts` since it isn't a file this task owns; a future task
  wiring up `app/api/**` may still use the singleton normally from within Next.js.
- **`one()` helper in `seed.ts`.** `noUncheckedIndexedAccess` (already on in `tsconfig.json`)
  makes every `const [row] = await tx.insert(...).returning(...)` destructure `T | undefined`.
  Rather than sprinkle non-null assertions, `seed.ts` has a tiny `one(rows)` helper that throws if
  a single-row insert didn't return exactly one row — this reads as intentional defensiveness
  (a seed script is exactly the place you want a loud failure over a silent `undefined`) rather
  than a typecheck workaround.
- **`scripts/smoke.ts` re-implements, rather than imports, the round-trip normalization/diff
  logic** from `lib/render/render.test.ts`. It was written to be read-only, dependency-free of
  `*.test.ts` files, and runnable outside the test runner (`node --experimental-strip-types
  scripts/smoke.ts`, not `node --test`) — importing a `.test.ts` module would have pulled in
  `node:test`'s `test()` registration as a side effect. The normalization function and the
  documented-divergence string are kept byte-identical to the test's copies by inspection; if
  `lib/render/render.test.ts`'s round-trip fixture or normalization ever changes, this file should
  be updated to match (noted in its own header comment).
- Two shared `db`/`latex` containers were already running under the `resumix` compose project
  name (from the main checkout) and occupying ports 5433/8080; I used them rather than start a
  second, port-colliding `t5` stack. They were confirmed healthy, on the current migration set,
  and empty before use.
