# T15 — feedback widget: popover, drop-on-button, better issue body

Branch: `feat/t15-feedback-polish`. Worked in the main checkout, not a
worktree — three small changes to one already-merged feature, no other task
in flight touching `components/feedback/**` or `lib/feedback/**`.

## Why

T13 shipped the feedback loop's push half and it works, but using it in
anger surfaced three frictions, all reported by the owner:

1. The form was a centred modal over a dimmed backdrop. A bug report is a
   description of what is on screen, and the backdrop was covering the
   evidence — you would open the form, realise you could no longer see the
   thing you were describing, and close it again.
2. The normal way a screenshot gets taken here is ⌘⇧4, which leaves a PNG on
   the desktop. Filing it meant: click the button, find the dropzone, go back
   to the desktop, drag. The button is already the thing you are aiming at.
3. Every issue's **Page** line was a full URL, so the same page read as two
   different strings depending on whether the report came from a dev server
   or prod, and neither the browser nor the deployment was skimmable.

## What was built

### The form is a popover (D-022)

`FeedbackDialog` renders anchored at `right-4 bottom-16` — above the button,
no `inset-0` backdrop, `role="dialog"` **without** `aria-modal`, since it no
longer is one. Escape and Cancel still close it; a click anywhere else on the
site now does too.

The outside-click listener deliberately lives in `FeedbackWidget`, not in the
panel. Both the button and the panel are wrapped in one ref'd `<div>` (both
children are `fixed`, so the wrapper is inert in the flow), and the listener
ignores `pointerdown` inside it. Scoping it to the panel alone is the obvious
implementation and it is wrong: `pointerdown` outside would close, then the
button's own `click` would reopen, remounting the form and destroying a
half-written report. Clicking the button while open therefore toggles shut.

`pointerdown` rather than `click` so the panel goes away as the user reaches
for whatever they clicked, and so a drag that begins outside and ends inside
still counts as outside.

### The button is the dropzone (D-022)

Dropping an image on "Give feedback" attaches it and opens the form. Dropping
a second one swaps the image **without** bumping `formKey`, so the remount
that normally blanks the form does not happen and typed text survives. That
required lifting `screenshot` out of the panel into the widget — it can now
arrive while the panel is closed — while `kind`/`description` stay local and
the panel stays presentational.

A window-level drag watcher does two things:

- Lights the button up ("Drop screenshot") whenever a file is dragged
  anywhere over the page, because a drop target nobody knows about is not a
  feature. `aria-label` is pinned to "Give feedback" so the accessible name
  does not change mid-drag.
- `preventDefault`s a file drop that **missed**. The browser's default is to
  navigate to the raw image, which throws away the page the user was about to
  report on. Guarded by `isFileDrag`, so dnd-kit's reordering drags (pointer
  events, no files) and text drags are untouched.

`dragenter`/`dragleave` fire per element crossed, so the watcher counts depth
rather than flipping a boolean, which would flicker off over every child.

### Route and origin are separated in the issue (D-023)

```
**Type:** Bug report
**Page:** `/resume/5b21843a-…?tab=template`
…
<details><summary>Environment</summary>

- Origin: http://localhost:3000
- Browser: Chrome 142 on macOS
- Viewport: 1512x857
- Submitted: 2026-09-19T15:04:05.123Z
- User agent: `Mozilla/5.0 (Macintosh; …`
```

Split server-side in `issueBody` with `new URL`, so **the wire contract is
unchanged** — the client still posts one `url` field. An unparseable value
passes through raw rather than being dropped; a malformed URL is still
evidence.

`lib/feedback/user-agent.ts` turns the UA string into `Chrome 142 on macOS`.
Hand-rolled, not a dependency: UA-parsing libraries carry hundreds of regexes
for crawlers and feature phones and this has exactly one caller. The whole
algorithm is the ordering of two lists — every Chromium browser also claims
`Chrome` and Chrome claims `Safari`, so Edge/Opera/Samsung are tested first;
an Android UA says `Linux` and an iPad in desktop mode says `Mac OS X`, so the
mobile platforms are tested first. The raw string stays in the body directly
underneath, which is what makes a hand-rolled parser safe here: a wrong parse
costs nothing.

`markdownLink` was deleted with its last caller. `encodeParens` survives —
still needed for the screenshot image URL.

## Decisions worth knowing

1. **Non-modal is the point, not a simplification.** The dimmed backdrop was
   hiding the subject of the report. Everything else — outside-click
   dismissal, the widget owning the listener, the button toggling — follows
   from that one change.
2. **The screenshot moved up to the widget**, because a drop on the button
   can happen with the panel closed. Kind and description stayed in the panel.
3. **A missed file drop is swallowed.** The alternative is the browser
   navigating away from unsaved work, which is a worse default than "nothing
   happened".
4. **The issue body changed; the endpoint did not.** `POST /api/feedback`
   still takes one `url`. Splitting it in the formatter keeps it a pure,
   unit-tested function and avoids a wire change for something derivable.
5. **Backticks are stripped from code spans, not escaped.** Nothing that
   lands in one (a route, a UA string) can legitimately contain one, and an
   unbalanced backtick breaks the rest of the line.

## What was verified

- `npm run verify` green end to end: format, lint, typecheck, `next build`,
  **182 unit tests / 0 skipped**, reseed, smoke (round-trip match, `ok=true,
  pages=1`), **22 Playwright tests**.
- New unit tests: `lib/feedback/drag.test.ts` (5) and
  `lib/feedback/user-agent.test.ts` (4). `issue.test.ts` reworked for the new
  body: route-without-host, origin in Environment, prod and localhost
  producing the same Page line, an unparseable URL, a missing user agent, and
  backticks in both a parsed and an unparsed URL.
- New e2e in `e2e/feedback.spec.ts` (3): a drop on the button attaches and
  opens; a second drop preserves typed text; the popover dismisses on an
  outside click and toggles on the button. Native file drags have no
  Playwright API, so `dragPngOnto` builds a real `DataTransfer` in the page
  and dispatches `dragover`/`drop` — `setInputFiles` would bypass the very
  path under test.
- Eyeballed in a real browser at 1280×800: closed, open with text, a file
  dragged over the page (button reads "Drop screenshot"), dragged over the
  button, and dropped.
