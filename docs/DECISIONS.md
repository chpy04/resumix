| D-021 | Feedback screenshots are committed to an orphan `feedback-assets` branch via the Git Data API and linked at that commit's sha, rather than attached to the issue                               | GitHub's issue API has no attachment endpoint — the web UI's uploader is not public API. Linking at a sha makes the URL immutable, and the repo being public lets GitHub's image proxy render it inline. **If the repo ever goes private, inline rendering breaks** and the screenshot needs hosting by the app instead                           | the Contents API (one call instead of five, but caps a file at 1 MB — well under a Retina screenshot); base64 in the issue body (bloats it and renders as a wall of text); not supporting screenshots (the single most useful part of a bug report)                                                                                                                                                                                             |
| D-023 | The feedback form is a non-modal popover anchored to its button, and the button itself is a screenshot dropzone                                                                                | a bug report describes what is on screen, and a full-page modal with a dimmed backdrop hides the evidence; anchoring the form to its corner keeps the page readable and clickable, which also makes "click anywhere else" the natural dismissal. | D-024 | The issue body's **Page** line is the route only; the origin and a readable browser name go in the Environment block                                                                           | the route names a page in this codebase, so two reports about the same page read as the same page whether they came from prod or a laptop — `localhost:3000/resume/x` and `resumix.app/resume/x` were two different strings to skim and to group.
